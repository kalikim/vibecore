# Repository handoff

Before working on Vibecore, read `PROJECT_MEMORY.md` and the relevant source files.
Treat the memory as a dated snapshot, and verify it against the current checkout.

Check `git status --short` and preserve existing user changes. Distinguish local
implementation, passing tests, published code, and live deployments in reports.
Do not reuse completion percentages from prior conversations as measured facts.

After material implementation changes, update `PROJECT_MEMORY.md` with source
evidence, checks actually run, known limitations, and the next task. Never place
credentials or raw sensitive output in that file.
